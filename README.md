# VERIFIABLE RAG — PDF RAG QA with Claim-Level Hallucination Verification

A simple, full-stack implementation of the PIER-QA idea plus the extended
feature you described: after the system generates an answer from a PDF,
it splits the answer into individual factual claims, checks each one
against the retrieved evidence, re-retrieves and regenerates if a claim
isn't supported, and abstains rather than guessing if it still can't
find enough evidence.

```
Generate → Claim Extraction → Evidence Verification → Re-retrieval → Regeneration / Abstention
```

**Stack** — no complex billing, no cloud infrastructure required:
- **Backend:** Python + FastAPI
- **Embeddings:** `sentence-transformers` (local, free, runs on your machine)
- **Vector store:** ChromaDB (local file-based, free)
- **LLM:** any OpenAI-API-compatible provider — Groq's free tier 
- **Frontend:** plain HTML/CSS/JS (no build step, no npm required)

## 1. Project structure

```
pier-qa/
  backend/
    app.py                  # FastAPI app (routes: /upload, /ask, /documents)
    modules/
      pdf_processor.py      # PDF -> text -> chunks
      embedder.py           # local embedding model
      vectorstore.py        # ChromaDB wrapper
      llm_client.py         # OpenAI-compatible LLM wrapper
      claim_verifier.py     # the extended feature: verification loop
    requirements.txt
    .env.example            # copy to .env and fill in your LLM key
  frontend/
    index.html
    style.css
    script.js
```

## 2. Setup in VS Code

1. Open the `verifiable-rag/` folder in VS Code.
2. Open a terminal (`` Ctrl+` ``) and set up the backend:

   ```bash
   cd backend
   python -m venv .venv
   source .venv/bin/activate      # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   cp .env.example .env
   ```

3. Get a free LLM API key — **Groq is the simplest, no billing at all**:
   - Go to https://console.groq.com/keys, sign up, create a key.
   - Paste it into `backend/.env` as `LLM_API_KEY=...`.
   - (The `.env.example` file also shows how to use OpenAI or a fully
     local Ollama model instead, if you'd rather not use any API key.)

4. Start the backend:

   ```bash
   uvicorn app:app --reload --port 8000
   ```

   First run will download the small local embedding model
   (~90MB, one-time). Leave this terminal running.

5. Open the frontend: in VS Code, right-click `frontend/index.html` →
   **"Open with Live Server"** (install the free "Live Server" extension
   if you don't have it), or just double-click `index.html` to open it
   in your browser directly — no build step needed.

## 3. Using it

### A. Verified RAG Q&A
1. Upload a PDF or supported file (research paper, textbook, financial report, etc.).
2. Ask a question about it.
3. You'll see:
   - **The final, verified answer**
   - **Hallucination Risk Percentage** — exact percentage metric (e.g. `Hallucination Risk: 0%`) based on verified vs ungrounded atomic claims
   - **Claim verification breakdown** — each factual claim labeled `SUPPORTED`, `CONTRADICTED`, or `UNSUPPORTED` against retrieved text with citations
   - **Sources used** — exact chunks retrieved from your document

### B. External LLM Hallucination Checker (Built-in Auditor)
1. Switch to the **LLM Hallucination Checker** tab in the top navigation.
2. Copy-paste any response generated by **ChatGPT, Claude, Gemini, Llama**, or any other LLM.
3. Choose your reference ground truth:
   - **Indexed Documents**: Uses files already indexed in VerifiableRAG.
   - **Paste Context**: Paste custom reference text, guidelines, or textbook paragraphs directly.
   - **Both**: Evaluate against both uploaded documents and pasted context.
4. Click **"Calculate Hallucination Risk Percentage"**.
5. You'll get:
   - **Hallucination Risk Gauge**: Large visual percentage (0–100%) and risk tier (None, Low, Moderate, High, Critical).
   - **Factual Grounding Scorecard**: Hallucination Rate, Grounding Verified Rate, Unsupported Rate, and Contradiction Rate.
   - **Visual Grounding Heatmap**: The pasted answer color-coded sentence-by-sentence (green = verified, red = hallucinated, orange = contradicted).
   - **Atomic Claim Breakdown**: Each fact extracted, evaluated, and explained with verbatim source citations.
   - **Export Audit Report**: Download complete Markdown audit reports or copy executive summaries.

## 4. API Endpoints

- `GET  /health` — Service health check
- `GET  /documents` — List all indexed documents
- `POST /upload` — Upload and index document files (PDF, DOCX, TXT, MD, PPTX, XLSX, images)
- `POST /ask` — Verified RAG question answering with hallucination risk percentage
- `POST /ask/stream` — Streaming SSE verified Q&A
- `POST /verify-external` (alias `/check-hallucination`) — Audit external LLM answers for hallucinations against documents and/or pasted context
- `POST /summarize` — Generate document summaries
- `GET  /export/{doc_id}` — Export indexed chunks as plain text

## 5. Notes & extension points

The claim-verification engine (`backend/modules/claim_verifier.py`) calculates hallucination metrics via:
$$\text{Hallucination Percentage} = \frac{\text{Unsupported Claims} + \text{Contradicted Claims}}{\text{Total Claims}} \times 100\%$$

Features:
- Deterministic regex & numeric guards preventing invented numbers/percentages
- Automatic sentence-to-claim alignment for visual heatmaps
- Cross-document conflict detection
- Graceful offline/lexical fallback verification when LLM API keys are unset or rate-limited

## 6. Troubleshooting

- **"Connection refused" in the frontend** → make sure `uvicorn` is still running in the terminal (`cd backend && uvicorn app:app --reload --port 8000`).
- **401/403 from the LLM** → double check `LLM_API_KEY` in `.env` and that `LLM_BASE_URL`/`LLM_MODEL` match the provider you picked.
- **Offline / No API Key** → The system automatically falls back to deterministic lexical grounding verification.
